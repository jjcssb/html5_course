# 小游戏合集（微信小程序）

一个原生微信小程序小游戏合集，包含 **2048** 和 **数字华容道（3×3 / 4×4）**，接入微信云开发，实现玩家资料、云端最佳、排行榜、每日挑战、成就和云端存档。

## 功能

### 2048

- 4×4 棋盘，上下左右滑动合并数字。
- 每次有效移动后生成一个新数字：90% 为 2，10% 为 4。
- 每块每步最多合并一次，得分等于本次合并产生的新数字之和。
- 首次合成 2048 弹出胜利提示，可继续游戏，同一局不重复弹出。
- 满盘且横竖都无法合并时结束。
- 最高分、历史战绩（最近 10 局）保存在本地。
- 三套主题、音效和震动反馈。
- 每日挑战使用服务端生成的固定种子，全站同一天同一局。

### 数字华容道

- 3×3（8 个数字）和 4×4（15 个数字）两种尺寸。
- 滑动方向等于数字移动方向，每次只移动空格相邻的一个数字。
- 打乱从完成态随机走合法步，保证局面一定有解。
- 首次移动开始计时，记录步数和用时。
- 每种尺寸独立保存最佳记录。
- 3×3 使用 A* 搜索给出最优下一步和最少步数。
- 4×4 使用打乱路径的逆序作为保证解；路径较长时演示前二次确认。
- 每日挑战同样使用服务端固定种子。

### 玩家与云端

- 微信静默登录，云函数通过 `openid` 识别玩家。
- 新玩家可设置头像、昵称、性别：
  - 6 个内置头像；
  - 或使用 `open-type="chooseAvatar"` 选择微信头像，上传云存储后保存 `fileID`。
- 云端保存每个玩家的各游戏最佳成绩和成就。
- 排行榜支持 2048、3×3、4×4，只有总榜和本周榜。
- 排行榜默认总榜，支持分页和“我的最佳/我的排名”。
- 每日挑战保留玩法，但不单独生成今日挑战排行榜。
- 华容道最佳按“步数少优先，步数相同再比用时”排序。
- 云端存档：有进度时退出自动保存，首页可以继续上一局。
- 成就系统：2048 初胜、3×3/4×4 入门、每日挑战、速通 3×3、4096 俱乐部。

### 界面与体验

- 首页、2048、华容道、排行榜、资料页统一卡片式视觉和暖色主题。
- 子页面顶部提供“游戏合集”返回入口。
- 浅色、深色、复古三套主题。
- 棋盘区域拦截页面滚动，避免滑动时页面跟着动。
- 云环境不可用时仍可单机玩，排行榜显示未连接状态。

## 技术栈

- 微信小程序原生：WXML / WXSS / JavaScript。
- 微信云开发：云函数、云数据库、云存储。
- 纯函数游戏逻辑，可在 Node 中直接测试。
- Node.js 内置 `node:test` 做单元测试。
- `miniprogram-automator` 做模拟器页面级验证。

## 核心实现

### 2048 棋局

- `utils/board.js` 负责棋盘移动、合并、计分和随机生成。
- `utils/engine.js` 负责状态机：`playing`、`won`、`over`，以及重开、继续游戏和历史战绩。
- 棋盘在页面中保存为 4×4 嵌套数组，动画层把每个方块转换成绝对定位的 `tiles`；移动前先计算目标位置，再更新数据和动画锁。
- 随机源使用带种子的 mulberry32，保证同一 seed 可以重放。
- 提交成绩时上传 `seed` 和完整滑动方向数组；云函数从初始棋盘重放，对比分数、步数和最终棋盘。

### 数字华容道

- `utils/klotski.js` 用一维数组表示棋盘，`0` 表示空格。
- 完成态固定为 `1..N-1, 0`。
- 打乱时从完成态开始随机执行合法移动，同时记录路径，因此不会生成不可解局面。
- 4×4 的“保证解”就是打乱路径的逆序：先撤销用户已经走的步，再补上打乱路径。
- 3×3 使用 A*（曼哈顿距离启发）求最短解，页面只取下一步作为提示。
- 最佳成绩比较规则：步数少优先；步数相同时用时短优先。

### 手势与动画

- `utils/gesture.js` 统一处理触摸开始、移动、结束、取消。
- 一次手势最多触发一次移动，滑动距离低于阈值不响应。
- 处理触摸取消、多指和快速连续滑动。
- 2048 使用动画锁和待处理方向队列，避免快速滑动导致棋盘状态错乱。
- 华容道棋盘区域使用 `catchtouchmove`，防止页面滚动。

### 云函数与数据

云函数统一入口为 `cloudfunctions/api/index.js`，通过 `action` 分发：

- `login`：获取 `openid`，创建或返回玩家档案。
- `updateProfile`：保存昵称、性别、头像、`avatarUrl`。
- `submitRun`：校验并保存成绩。
- `leaderboard`：按游戏和周期查询排行榜。
- `daily`：返回当天各游戏的固定种子。
- `saveState` / `loadState` / `clearState`：云端存档。
- `resetMyData` / `resetMyScores`：清理当前玩家数据。

云数据库集合：

- `players`：每个 `openid` 一条，保存昵称、头像、性别、各游戏最佳、总场次、成就、存档。
- `rankings`：按 `game + periodKey` 保存排行榜记录，周期为 `all` 或 `week:YYYY-Www`。

成绩校验：

- 2048：客户端上传 `seed`、`directions`、`score`、`moves`；服务端重放后逐项对比。
- 华容道：上传 `size`、`seed`、`directions`、`moves`、`timeMs`；服务端重放完成态并校验步数和时间范围。
- 每日挑战：服务端校验日期和种子，过期或种子不一致直接拒绝。

最佳比较：

- 2048：分数降序；分数相同比步数。
- 华容道：步数升序；步数相同比用时。
- 历史脏数据 `moves=0` 视为无效记录，不会卡住新成绩。

### 资料、头像与成就

- `utils/profile.js` 和 `cloudfunctions/api/profile.js` 保持同一份头像/性别选项。
- 头像优先显示 `avatarUrl`，没有则显示内置 emoji。
- 昵称长度、性别、头像值都由云函数校验，客户端不能直接写数据库。
- 成就由服务端根据成绩和每日挑战记录解锁，客户端只负责展示。

### 本地存储与降级

- 最高分、历史战绩、主题、音效、华容道最佳等使用 `wx.setStorageSync` 保存。
- 存储读取失败、内容损坏或类型错误时安全回退到默认值。
- 云开发未初始化、网络失败或云环境不可用时，游戏本身仍可玩；排行榜和每日挑战显示相应错误状态。

## 运行

1. 用微信开发者工具导入项目根目录。
2. 在开发者工具中开通云开发，创建一个环境。
3. 把环境 ID 填入 `config/cloud.js` 的 `ENV_ID`。
4. 在云数据库创建 `players` 和 `rankings` 两个集合。
5. 右键 `cloudfunctions/api`，选择“上传并部署：云端安装依赖”。
6. 重新编译小程序。

云环境 ID、集合名和云函数名都集中在 `config/cloud.js`，换环境时只改这一处。

## 测试

```bash
npm test              # 游戏逻辑单元测试
npm run test:config   # 页面/资源/事件/同步文件静态检查
```

游戏逻辑与页面解耦，核心规则可以在 Node 中直接测试，不依赖微信开发者工具。

## 说明

- 小程序端不依赖外部图片、CDN 或网络字体，音效为本地 WAV。
- 云端数据库只保存游戏所需的最小玩家数据。
- 每日挑战只保留玩法，不生成今日排行榜；成绩进入总榜和本周榜。
